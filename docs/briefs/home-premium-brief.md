# 首页改版任务书（只谈前端：美观、专业、合理）

> 范围：只管前端的样子和交互。数据库、合规、上线后的指标暂不涉及。
> 分工：Claude 定设计、写规范、审代码；Codex 按规范写代码。

## 1. 现状（实测，不是感觉）

- **字号太乱**：光 `P04-HomeMaison.module.css` 一个文件里就有 **19 种字号**（10、10.5、11、12、13、14、15、24、25、28、32、34、36、42、44、50、54、64 px 等）。专业 App 通常只用 6–7 级。
- **圆角太乱**：同一个文件里有 7 种圆角（2、5、8、12、16、18、999 px）。
- **卡片风格太多**：玻璃卡、深色漆面卡（Foundation RWA 那个玻璃球）、白卡、压在照片上的行情条，至少 4 种。
- **图片风格不统一**：金条、芯片、火箭是三种不同的 3D 渲染风格，像 AI 生成的。玻璃球是纯装饰。
- **每块的标题都一样大**（约 28px 粗体），页面没有轻重，节奏单调。
- **数字格式不统一**："US79.94亿"、"US$48亿"、"4.897%"、"3,945.29" 各用各的写法。
- **说明文字太小**：来源、时间、"延迟"这些字大多只有 10–11px，看不清。
- **登录后第一屏是广告**：标语加房子大图占了约 60%，资产卡被挤到下面。
- **页面没有尽头**：社区流一直加载，刷不完。

## 2. 顶尖专家会做、但原题目没要求的事（前端范围）

1. **先做规范，再做页面**：定下字号阶梯（例如 11 / 13 / 15 / 17 / 20 / 28 / 40）、8 点间距网格、3 种圆角、2 种卡片样式，写进 `docs/design-system.md`，并加检查脚本防止又加出新字号。
2. **数字排版**：所有数字用等宽数字（tabular-nums）；单位比数字小一号、颜色更浅（"79.94 亿 USD"）；小数位按资产类型固定；负号用真正的 "−"，不用 "-"；千分位统一。
3. **中英文混排**：中文和数字、英文之间留间距，标点用全角，行尾不出现孤字。
4. **财务数字不跳数**：只用 150–200ms 的淡入；骨架屏的形状和真实内容一样，加载完页面不跳。
5. **状态都要画**：加载中（骨架屏）、加载失败（一行字加"重试"）、余额为 0（首次充值引导）、待到账，每种样子都要设计。
6. **极端内容测试**：最长的产品名、亿级金额、负数、0、阿拉伯语从右到左、系统大字号。
7. **图片统一**：资产图片统一成一种风格（同一光线、同一角度、同一背景），或者改用代码字母徽章（如 GOLD、NVDA）。去掉纯装饰的 3D 物体。
8. **层级靠字重和留白，不靠颜色和框**：区块之间多留白；区块里面用细线分隔，不用"卡片套卡片"。
9. **深色模式一样精致**：深色不是简单反色，阴影、分隔线、图片亮度都要单独调。
10. **触感细节**：按下有反馈，点击区域不小于 44px，页面有明确的结尾。

## 3. 从最原始的素材开始

- **真机上的真实页面**：3 种手机 × 浅色/深色 × 中文/英文，截图和录屏，不用设计稿。
- **真实的极端数据**：线上最长的产品名、最大的金额、负数涨跌、空列表。
- **代码里的真实数值**：`P04-HomeMaison.module.css` 和 `components/home/*.module.css` 里所有的字号、间距、圆角、颜色，全部统计出来。
- **字体本身**：Satoshi 和 Noto Sans SC 的数字字形、行高、等宽数字是否支持。
- **竞品的真机截图**：Revolut、Robinhood、moomoo、Binance、Wise 登录后的首页。在同样的 375px 宽度下截图，并排对比字号、间距、数字写法。
- **所有语言的文案长度**：7 种语言中最长的那一版，放进去会不会撑破布局。

## 4. 方法和工具

- **审计脚本**：统计每个 CSS 文件里的字号、间距、圆角、颜色种类，改版前后对比（目标：首页字号 ≤ 7 种、圆角 ≤ 3 种）。
- **黑白线框**：先只用灰度定层级，再上颜色和质感。
- **眯眼测试**：把截图模糊后看，最重要的东西是不是还最显眼。
- **并排对比**：我们和 5 个竞品，同尺寸截图拼成一张图，一起看。
- **Playwright 截图矩阵**：机型 × 主题 × 语言 × 状态（加载 / 空 / 失败 / 正常），自动截图，改版前后逐张对比。
- **axe-core**：对比度和读屏检查。
- **Lighthouse 的 CLS 检查**：加载过程中页面不能跳。
- **Codex 交叉审查**：Claude 出设计，Codex 只看不改，专门挑毛病；有分歧写下理由，再决定。

## 5. 除了 Claude 和 Codex，什么能证明结果是对的

- **规范检查脚本**：首页不出现规范以外的字号、圆角、颜色（结果可以重复跑）。
- **axe**：0 个严重问题，所有文字对比度 ≥ 4.5:1。
- **CLS ≤ 0.1**：加载时页面不跳。
- **截图矩阵**：所有机型、主题、语言、状态都没有错位、截断、重叠。
- **5 秒测试**：找 3–5 个没见过这个页面的人，看 5 秒后问："你的余额是多少？""想邀请朋友点哪里？"
- **竞品并排图**：放在一起看，不显得比它们廉价。

## 6. 改写后的题目

> 请只从前端（美观、专业、合理）重做 A-REIT 登录后的手机首页。
>
> **先做规范：**
> - 统计现有首页的字号、间距、圆角和卡片样式，定出新规范：字号 ≤ 7 级、8 点网格、圆角 ≤ 3 种、卡片 ≤ 2 种，写进 design-system，并加检查脚本。
>
> **素材：**
> - 真机截图（3 机型 × 2 主题 × 2 语言）
> - 线上的极端数据
> - 5 个竞品同尺寸真机截图
> - 7 种语言最长的文案
>
> **设计：**
> - 资产卡是登录后第一屏的主角，广告大图只给未登录用户看。
> - 数字统一用等宽数字和统一格式，不跳数。
> - 每个模块都画出加载、失败、空、正常四种状态。
> - 图片统一成一种风格。
> - 区块标题分主次，区块里用细线不用嵌套卡片。
> - 推荐奖励卡紧跟资产卡，样式克制。
> - 首页有结尾，社区只放 2 条预览。
> - 深色模式单独调过。
>
> **流程：**
> 1. 黑白线框
> 2. Codex 只看不改地审查
> 3. Claude 定稿
> 4. Codex 实现
> 5. Claude 审代码
>
> **验收：**
> - 规范检查脚本通过
> - axe 0 个严重问题
> - CLS ≤ 0.1
> - 截图矩阵无错位
> - 3–5 人的 5 秒测试通过
> - 竞品并排图不显廉价
