# 社区 + 邀请：后端计划（2026-10-28）

前端已经上线（r99）。下面三项需要改后端（API + 数据库）。都在 `apps/api` 里做，一项一个提交，逐项上线。

## 读代码得到的事实
- 邀请关系在 `app.referral_edges`：`inviter_user_id` → `invitee_user_id`（一级）。链接被打开记在 `app.referral_attributions`（每次点击一行），首次申购量化记在 `app.referral_quant_first_subscriptions`。
- 社区资料 `app.community_profiles` 有 `user_id`，帖子 `app.community_posts` 用 `profile_id` 关联作者。
- 账本数据：量化每天的到账在 `app.quant_payouts`，预测下注和结果在 `app.prediction_bets`。

## 1. 「我的圈子」：你邀请的人在社区里排前面
- 新接口 `GET /v1/community/me/circle`：返回我直接邀请的人里**有社区资料的人**（头像、昵称、handle），加上邀请我的那个人。
- 社区「热门 · 最新」后面加一个「圈子」：只看圈子里的人发的帖子（`GET /v1/community/feed?scope=circle`）。圈子里的人发的帖子，在热门和最新里也会标一个小字「你邀请的」或「邀请你的人」。
- **隐私（需要你决定）**：现在的邀请名单是打码的。做了这一项，邀请人就能看到被邀请人的**社区昵称**（社区资料本来就是公开的，但「是我邀请的」这层关系以前看不到）。
  - 我的建议：在社区资料设置里加一个开关「让邀请我的人在圈子里看到我」，**默认打开**，用户可以随时关掉。邮箱、真实姓名、资产都永远不显示。
- 不需要新表，只读 `referral_edges` 和 `community_profiles`。

## 2. 「账本已验证」的收益帖
- 新表 `app.community_post_proofs`：`post_id`、`user_id`、`kind`（`quant_day` / `prediction_win`）、`ref_id`（到账记录或下注的 id）、`pct`、`trade_date`、`created_at`；同一条记录只能发一次。
- 发帖接口加一个可选字段 `proof: { kind, refId }`。服务器自己查账本：这条记录必须属于发帖人、必须是盈利、在 30 天内；涨幅由服务器算，前端传的数字一概不用。
- 帖子接口返回 `proof`。前端在帖子里显示一张小卡：产品名、日期、大号涨幅、「账本已验证」，下面**自动加**「历史表现不代表未来收益」。卡片不能编辑。
- 分享卡（ShareWin）上加一个按钮「发到社区」，直接带上这条记录发帖。
- 只显示百分比，不显示金额。

## 3. 邀请转化统计
- 不需要新的统计工具：现有的表已经够了。
- 新接口 `GET /v1/referral/funnel`：我的链接被打开几次（`referral_attributions`）、注册几人（`referral_edges`）、首次申购几人（`referral_quant_first_subscriptions`），按最近 30 天和全部两种时间。
- 邀请页加一行：「链接打开 12 次 · 注册 3 人 · 首次申购 1 人」。
- 管理后台加同样的总数（全站），方便看哪种分享最有效。（如果后台要按「帖子分享 / 海报 / 直接链接」分开统计，需要在 `/r/` 记一个来源参数，也就是给 `referral_attributions` 加一列；这个可以第二步再做。）

## 上线步骤（每项都一样）
1. 写迁移（只加表和列，不改、不删已有数据）和接口，加单元测试。
2. 本地跑 API 测试；前端用 mock 截图。
3. 合并 main、推送。
4. **数据库迁移需要你确认**（按约定，数据库改动先问你）。确认后：在 Oracle 上 `docker build` API 镜像，执行一次迁移，切换容器，记录回滚镜像。
5. 部署前端 Worker，线上检查，记录版本号。

## 需要你决定的事
1. 圈子的隐私：用「默认打开、可以关掉」的开关，可以吗？
2. 三项的顺序：我建议 **3 → 2 → 1**。转化统计最简单，也最有用，马上就能看到效果。收益帖第二，它是最大的不同。圈子最后，因为它涉及隐私。
