# 全后台单人审批政策

日期：2026-10-09，北京时间。用户明确要求所有需要两人审批的操作改为一人。

状态：隔离工作区已实现并验证，尚未合并、推送或部署。本批没有对生产用户调账、批准提现或恢复资金开关。

## 覆盖范围

| 操作 | 当前实现 |
| --- | --- |
| 审批中心 | 有权限的申请人可以批准或驳回自己的申请；明确确认并保留决定人与时间。 |
| 人工提现审批 | 一次管理员批准满足人工审批数量；批准人也可以执行。提现必须先通过原有风控、状态和执行开关检查。 |
| 恢复提现执行 | 同一管理员可以提交恢复申请并明确批准；环境配置关闭执行时仍不可恢复。 |
| 账本调整 | 同一管理员可以申请、批准、入账；用户管理的单人调账不再受旧自审批开关限制。 |

管理网关原有角色和各操作权限不变。核心审批与账本接口仅对守卫认证的服务通道委托网关权限检查，普通管理员会话仍检查核心 RBAC。没有给业务库中的审计身份增加权限。

同一用户提交相同操作编号防重复入账、余额锁、金额精度、不可透支、复式记账和不可变流水保持原样。恢复资金执行仍走申请和批准接口，不能用普通开关更新绕过确认。审批中心点击取消不会提交决定。

## 数据库与历史记录

新增迁移：`1791532800000-single-administrator-approvals.ts`。

- 仅移除 `admin_approval_requests` 与 `operational_switch_change_requests` 中申请人与决定人必须不同的 CHECK 约束。
- 账本同类约束已由此前迁移 `1791446400000-single-operator-ledger-adjustments.ts` 移除。
- 决定人、决定时间、有效状态、金额及入账证据约束保留。
- 不批量通过既有申请，不改写任何余额或历史提现政策快照。后台提现列表使用接口给出的当前所需审批数。
- down 恢复旧检查为 NOT VALID：保留已有单人审批历史，对新的写入恢复旧约束。已在独立 PostgreSQL 测试 down/up。

旧迁移、旧错误码与历史审查文档中的双人描述用于版本历史，不代表当前运行政策。产品规范与任务板已有明确覆盖说明。
