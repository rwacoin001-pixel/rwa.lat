# 独立交易密码与站内收款门槛

## 已确认业务规则

- 每笔新提现必须输入独立六位 ASCII 数字密码，保留开头的零；不复用登录密码。平台键盘输入。
- 连续错误五次，账户锁定十五分钟；不同设备共享计数。成功验证清除连续错误计数。
- 忘记密码重设必须通过现有强身份验证，服务端暂停提现二十四小时。正常输入旧密码修改不增加冷静期，也不取消已有冷静期。
- 站内转账的接收方必须曾有一笔真实外部 USDT 充值已到账且严格大于 300 USDT。300 不满足；300.000001 满足。不按累计金额或当前余额判断。
- 赠送、演示充值、站内转账和已冲正的充值均不计入。现有真实通道为 manual-custody，资格要求链上确认和完整充值账本凭证。
- 该门槛只限制站内转账收款，不限制展示自己的收款二维码，也不新增提现的 300 USDT 门槛。
- 已验证邮箱、强身份验证、设备/地址限制、风控、限额以及现有单名管理员审批继续保留。

## 接口及数据

`GET /v1/security/transaction-password` 返回账户配置、剩余尝试次数、锁定/提现暂停截止时间及服务端时间。`POST` 子路径 `setup`、`change`、`reset` 需要已验证邮箱及近期强身份验证。

新提现提交 `transactionPin` 和现有 `reauthentication`。客户端不把密码放入交易草稿、存储、URL、幂等指纹或缓存。旧幂等凭证只有账户和完整交易意图匹配时可重放；不同意图必须冲突。

站内收款资格使用 `GET /v1/wallet/transfer-eligibility`，收款人确认使用现有转账目录下的 recipient 接口。前端校验仅作反馈，资金事务会重新验证资格、冲正和凭据版本。

新增迁移：`TransactionPassword1791619200000`。密码哈希、凭据版本、失败计数、锁定时间及重设冷静期存入 `app.transaction_password_credentials`；不存明文密码。

服务端新增 `TRANSACTION_PIN_PEPPER`：至少 32 字节的高熵稳定密钥，只放服务器密钥配置，不能放 `NEXT_PUBLIC_*`、代码仓库或数据库。首次生成后安全保管，不能每次部署重新生成，也不能未经迁移直接轮换。缺失时密码功能和新提现关闭，不绕过校验。哈希策略参考 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

## 发布顺序

1. 获得本批合并、推送、上线确认；发布前重新核对 GitHub main、运行 API 镜像、前端 Worker，保留其他 AI 后续发布。
2. 备份数据库及运行镜像/Worker 信息。在服务端受控配置中设置稳定 pepper，检查注入 API；禁止输出密钥。
3. 执行上述新增迁移并核对表/索引。该迁移不删除账户、余额、交易或历史记录。
4. 发布新 API，再发布对应前端。API 先发布的短窗口里，旧前端无法提交带密码的新提现，保持关闭而非放行。
5. 用只读接口检查配置、冷静期/锁定字段和收款资格；由用户在 Android/iOS PWA 检查密码设置、取消、错误和收款提示。真实资金操作由用户明确执行验证。

## 回退边界

- 前端回退不删除交易密码凭据、错误计数或重设冷静期。
- 该迁移的 `down` 仅在密码表为空时允许回退，必须使用 READ COMMITTED 事务并先锁表再判断，兼容 CI 的回退再应用检查；拒绝可能使用旧快照的隔离级别，存在任何密码安全记录时拒绝删除。需要专门审查的迁移才能改变这些记录。
- 新规则启用后，不能直接回退到不验证密码/收款资格的旧 API。故障时先关闭相关资金写入并修复，或在明确批准后实施保持规则的回退；保留现有资金开关和审计。
- 密码重设与提现并发时，凭据版本及冷静期必须在最终资金事务重新校验。

## 本地验证与预览

API 单元/HTTP/账本/真实 PostgreSQL 集成测试覆盖并发错五次、十五分钟解锁、二十四小时重设、精确充值门槛、冲正并发、幂等回放、旧资金行为、迁移历史保留及空表回退再应用；测试数据库为专用本地 `_test` 库，生产库没有测试写入。最终计数和日志在本批交付报告中记录。

本地独立预览入口 `/dev/funds-security`，仅开发环境开放、仅接本地模拟 API；生产显示不可用路由页面，不渲染样例组件。沿用 Next.js 的 notFound 机制，流式响应 HTTP 状态可能为 200，非流式为 404，不能只按 HTTP 状态验收。参见 [Next.js not-found](https://nextjs.org/docs/app/api-reference/file-conventions/not-found)。浏览器验证包括 18 项检查与 42 个宽度/主题/语言组合，具体证据保存在工作区 artifacts/funds-security-20261009。浏览器模拟不能代表 Android/iPhone 真机验收。
